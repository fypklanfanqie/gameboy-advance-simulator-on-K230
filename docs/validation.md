## 宿主与文件一致性

发布前原工程门禁的执行项全部通过：板端 Python 假件逻辑 229 项、音频探针 102 项、异步触摸 ASan/UBSan 159 项、核心多帧预算与缩放器、静态名字检查、API 导出及现有固件打包校验。最终门禁的卡内容检查因未挂载而 SKIP；此前独立部署已对四文件 fsync、逐字节回读通过，并确认 ROM/存档哈希未改变。

公开目录独立运行 `tools/verify_all.py`，明确区分 `PASS`、`FAIL`、`SKIP`。默认不需 ROM：覆盖 Python 逻辑、音频探针、名字/板端静态检查、模块 API、源码哈希、RTAPP 格式测试、异步触摸线程及逐像素缩放。提供仓库外的 ROM 后，可执行核心生命周期测试；提供卡路径后，可回读四文件。GitHub Actions 执行无需 ROM 的宿主门禁。

触摸线程和缩放器测试要求 ASan/UBSan 无诊断。mGBA 核心测试保留上游 UBSan 诊断完整日志，内存错误/AddressSanitizer 报告及断言失败均判失败；核心显示 PASS 不表示其上游全部算术 UB 已修复。任何新增诊断都应查看源位置，不可仅以总数判断为可忽略。

本次公开目录独立验证结果：默认门禁 **12 PASS、2 SKIP、0 FAIL**（未指定 ROM 和卡）。280 项固件源码哈希全部匹配；RTAPP 回归 138 项、部署保护 19 项、构建工具保护 5 项、触摸线程 159 项、缩放器 17 项全部通过。随后用仓库外本地 BPEE ROM 完成 60、120、300、900 帧四组核心测试，每组 33 项检查、0 失败，无 ASan 内存错误；未把 ROM 加入仓库。公开构建脚本通过语法及安装器保护测试，本次没有从新下载的 SDK 完成一次独立全固件构建。

## 存档与适用范围

开发卡已有 128 KiB 存档，曾备份并通过两个保存槽共 28 个数据区校验。代码保护短读/短写并周期性写盘；最新游戏进度和跨断电的实际恢复仍需游戏内验收，数据区校验不能代替该体验。部署源码本身不移动或改写 ROM 和 `.sav`。

目前验证聚焦一张匹配厂商镜像的 Hiwonder K230 和一款 GBA 游戏。不同游戏、屏幕、板型、固件 API、快速启动布局需要各自验证。

## 2026-10-13 存档修复复检

用户反馈游戏内保存并等待至少 30 秒后，重启仍恢复旧进度。宿主检查确认旧逻辑会把原生保存函数的负错误码打印为成功；本次修复缩短检查周期为 120 帧，忙或失败后 30 帧重试，校验临时文件长度并完整读回，内容变化后轮换旧文件为 `.sav.bak` 再提交。已有存档恢复明确失败时停止启动，退出等待会推进模拟帧以完成 Flash 定时事件。

板端 Python 假件测试 241 项、音频探针 102 项通过。默认门禁 12 PASS、2 SKIP、0 FAIL；更新开发卡后带卡门禁 13 PASS、1 SKIP、0 FAIL，四脚本逐字节一致，ROM 与存档哈希不变。此次外部 ROM 核心复测因 WSL 无法转换 Windows 读卡器 F: 路径而 SKIP；核心源码未修改，之前的多帧预算结果见上文。本次未重建或写入裸区固件。

新保存逻辑尚需游戏内保存后的断电重启验收。用户另反馈接入外接功放模块后只有背光、音量小；该硬件配置的线序、带载供电和播放均尚未确认，不能以宿主测试代替实物验收。

## 2026-10-13 室外闪屏与周期卡顿

用户随后确认存档已正常、能够接扬声器进入游戏，但标题和室内稳定，室外可操作场景整屏亮度闪动，拔掉扬声器后仍闪、仍卡。只读检查开发卡后，最新保存槽计数为 3；运行日志送音最长间隔约 170 ms，而显示提交平均约 1.3 ms。前一轮每 120 帧先写出 128 KiB 临时存档再比较，即使未变化也访问卡，属于本次消除的周期性停顿来源。

最初使用仓库外同一 ROM、存档副本及固定输入，在宿主核心运行 4800 帧，进入未白镇室外。`-O3` 加 `idleOptimization=detect` 时，2000 帧后相邻画面平均 RGB565 通道和变化超过 3 的次数为 154；改为 `ignore` 后为 0。随后用户视频及 RISC-V 对照确认关闭空闲探测后仍会变色，因此这组早期统计不足以认定空闲探测是根因。保留 `ignore` 以完整执行模拟指令，根因修复见下文；宿主统计不代替实屏验收。

新增 `gba.save_snapshot()` 只取得不可变内存快照。Python 对比上次已提交内容，未变化时不打开、查询或写入卡文件；变化时继续临时文件校验、备份轮换、提交失败重试。帧率和分段日志间隔为 600 帧。248 项 Python 假件测试通过，包含无变化时零文件访问与失败后缓存不更新的回归检查；外部 ROM 核心 60/120/300/900 帧测试通过，无 ASan 内存错误，原有上游 UBSan 诊断保留。

匹配提交的现有 SDK 已完成用户态固件构建，RTAPP 非 fake 检查、外层哈希、uImage CRC 及解包与 ELF 字节一致性验证通过。修复包写入开发卡 `rtapp_a`，回读验证成功，四个脚本逐字节一致；ROM、当前 `.sav` 和 `.sav.bak` 哈希均未改变，厂商 RTT 内核未写入。关闭空闲循环跳过后的真机 FPS、室外闪屏和音频流畅度仍待冷启动验收。

## 2026-10-13 视频复现与 RTC 修复

用户视频中人物静止时游戏画面反复变色。更新后的真机日志为约 59.8 FPS，run 约 6.5 ms、scale 约 0.71 ms、show 约 1.29 ms；送音 dropped=0、failed=0。帧率稳定并不能证明画面正确。

使用板用 GCC 12 编译 mGBA 核心、标准 Linux 启动库链接，并在 QEMU RISC-V 下运行仓库外 ROM 与存档副本。同一固定输入运行 3600 帧，最后 1200 个室外静止帧中，原版调色板变化 511 次，亮度相邻变化超过 3 共 509 次。渲染器 normalPalette 与原始调色板转换始终一致；降低优化或禁用类型别名优化只能改变发生频率。

固定时钟并追踪首次状态差异，发现 `util/formatting.c` 在未定义 `HAVE_LOCALTIME_R` 时提供直接返回空值的占位函数；`_rtcUpdateClock` 随后读取未初始化的 `struct tm`，把异常日期传给游戏。厂商 musl 已提供真实 `localtime_r`。仅补齐该特性宏并重编译后，同一 RISC-V 室外区间 1200 帧的调色板变化、亮度突变均为 0；无需降低核心优化级别。

回归检查覆盖闰日日期转换、游戏卡带 BCD 时钟、重复锁存、旧构建标志升级后强制重编译及未知标志拒绝覆盖。离线实验的启动库和运行环境与板端不同，故结果证明缺陷及修复方向，仍需新版用户态 RTAPP 的冷启动实屏和音频验收。ROM、存档及私有截图均不包含在公开仓库中。

匹配厂商 SDK 的新版用户态固件已完成构建。构建规则显式编译预生成的 `hle-bios.c`，避免同名客体 ARM 汇编被 RISC-V 编译器选中；mGBA 核心保持局部 `-O3` 并启用真实日期转换。非 fake 打包检查、uImage CRC、解包与构建 ELF 逐字节一致性均通过。RTAPP 写入开发卡 `rtapp_a` 后回读验证成功；厂商 RTT 内核未写入。

完整门禁使用仓库外 ROM 和开发卡执行，结果为 **14 PASS、0 SKIP、0 FAIL**。构建工具保护 19 项通过；核心在 60、120、300、900 帧预算下各 37 项检查通过，无 ASan 内存错误，既有上游 UBSan 诊断仍保留为 32/33 条。四个 Python 文件写卡后逐字节一致，用户 ROM、当前存档及备份哈希均保持不变。

部署时卡上现有约 59.8 FPS 的日志属于 RTC 修复前的运行，不能作为新版帧率证据。2026-10-13 用户按插卡冷启动、进入同一室外场景进行静止及移动对比的验收请求反馈：**“闪屏消失，声音流畅”**。这两项已获真机实屏观察和试听确认；该反馈未单独说明移动时卡顿，新版长时间性能、送音日志及不同场景的表现尚未补测。离线对照、自动门禁、部署回读和用户反馈分别记录，不用旧日志替代新版实测。
